# 01 - 项目演示与介绍

## 一、项目定位

`agent-customer-service` 是一个可靠 Agent 客服项目。它不是为了展示“能聊天”，而是为了讲清楚客服 Agent 在生产环境里必须守住的边界：

- 多轮会话要可追踪
- 回复必须基于知识证据
- 找不到证据时要明确兜底
- 高风险问题要转人工
- 知识缺口要沉淀为运营任务
- 所有能力要沿用脚手架的技术栈和工程习惯

核心公式：

```text
多轮会话 + RAG 证据 + 规则兜底 + 防幻觉边界 + 运营闭环 = 可靠 Agent 客服
```

## 二、演示主线

### 1. Agent 工作台

控制台首页围绕客服坐席视角设计：

| 区域 | 说明 |
|------|------|
| 指标区 | 展示会话、知识命中、兜底、转人工等运营指标 |
| 会话队列 | 选择不同用户会话，观察上下文延续 |
| 对话区 | 发送用户问题并展示 Agent 回复 |
| 证据区 | 展示本轮检索命中的知识条目 |
| 运营区 | 处理知识缺口、测试规则、关闭转人工工单 |

演示建议：

1. 选择一个已有会话。
2. 发送一个能命中知识的问题，例如“退货流程是什么？”
3. 观察回复中的 evidence、policy 与 confidence。
4. 再发送一个没有知识支撑的问题，观察知识缺口如何生成。
5. 发送一个需要人工处理的问题，观察转人工工单如何出现。

### 2. 知识缺口闭环

当用户问题没有足够证据时，系统不会强行编答案，而是：

1. 返回安全兜底回复。
2. 记录 `knowledge_gap`。
3. 在前端运营区展示待处理缺口。
4. 支持直接关闭缺口，或从缺口创建知识文章。

这个流程用于教学“防幻觉不是一句 prompt，而是产品、数据和流程共同约束”。

### 3. 规则兜底

规则测试区用于演示客服 Agent 的确定性边界：

| 规则 | 用途 |
|------|------|
| `NO_EVIDENCE_FALLBACK` | 没有知识证据时触发兜底 |
| `TRANSFER_THRESHOLD` | 命中特定风险或人工关键词时转人工 |
| `allow_answer` | 有足够证据时允许回答 |

规则不是替代 Agent，而是给 Agent 加护栏。

## 三、技术栈说明

### 与脚手架保持一致

| 层级 | 技术选择 | 教学意义 |
|------|----------|----------|
| 前端 | React + TypeScript + Vite | 控制台式产品体验，类型清晰 |
| 后端 | Go + `net/http` + `ServeMux` | 少框架、显式边界、易讲解 |
| 数据库 | PostgreSQL + pgx + SQL | 真实生产式持久化，不引入 ORM 隐式行为 |
| 日志 | `log/slog` JSON | 与脚手架一致的结构化日志 |
| 配置 | 环境变量优先 | 本地、容器、部署环境统一 |
| 质量门禁 | shell + Go test + Vite build | 每个阶段都能验证和提交 |

### 为什么这样选

这个项目最终是教学用的“从脚手架生长出来的 Agent 应用”。学生不需要重新学习一套新的底层技术，只需要观察：

- 客服 Agent 的领域模型如何抽象
- 会话、知识、规则、运营任务如何拆模块
- API 如何稳定下来
- 前端如何围绕真实工作流组织

## 四、整体架构全貌

```text
apps/console
  React 控制台
      |
      | /api/*
      v
cmd/platform-all
  Go HTTP API
      |
      +--> internal/customer   多轮会话、回复生成、转人工
      +--> internal/knowledge  知识文章、检索、知识缺口
      +--> internal/ops        指标、规则测试、运营动作
      |
      v
internal/platform/store
  Runtime interface
      |
      +--> in-memory store     课堂快速演示
      +--> postgres store      真实持久化
```

## 五、本节小结

学生完成本节后应该理解：

1. 这个项目是可靠客服 Agent，不是聊天玩具。
2. 当前工程已经继承脚手架技术栈和质量门禁。
3. 核心链路包括会话、知识检索、规则兜底、知识缺口、转人工。
4. 前端不是营销页，而是面向坐席和运营的工作台。
