# 00 - 环境准备与运行

本项目已经按 `infra-dev-scaffolding` 的工程习惯重构：前端是 React + TypeScript + Vite，后端是 Go + 标准库 HTTP，数据层是 PostgreSQL + pgx + SQL。学习时优先关注客服 Agent 的设计，底层运行方式与脚手架保持一致。

## 环境要求

| 工具 | 版本要求 | 说明 |
|------|----------|------|
| Go | 1.24+ | 后端服务与命令行入口 |
| Node.js | 20.19+ | 前端运行环境 |
| pnpm | 8.8+ | 工作区包管理 |
| PostgreSQL | 15+ | 生产式本地数据存储 |
| Docker | 可选 | 一键启动本地 PostgreSQL |

## 快速启动

### 1. 安装依赖

```bash
cd /Users/lvxianghe/project/anjing/opensource/agent-customer-service
pnpm install
go mod download
```

### 2. 启动本地数据库

```bash
pnpm db:up
pnpm db:migrate
```

默认连接配置：

```bash
ANJING_DATABASE_URL=postgres://agent:agent@localhost:15432/agent_customer_service?sslmode=disable
```

如果本机暂时没有 Docker，也可以直接使用内存模式运行后端。内存模式适合课堂演示 API 和前端交互，PostgreSQL 模式适合演示真实持久化。

### 3. 启动后端

```bash
ANJING_ADDR=:19002 go run ./cmd/platform-all
```

如果要连接 PostgreSQL：

```bash
ANJING_ADDR=:19002 \
ANJING_DATABASE_URL='postgres://agent:agent@localhost:15432/agent_customer_service?sslmode=disable' \
go run ./cmd/platform-all
```

验证接口：

```bash
curl http://localhost:19002/api/ops/dashboard
```

### 4. 启动前端

```bash
pnpm dev:console
```

浏览器访问 Vite 输出的地址。前端控制台通过 `/api/*` 访问后端。

## 质量校验

每次阶段性开发完成后运行：

```bash
./scripts/check-template.sh
./scripts/check-contracts.sh
go test ./...
pnpm build:console
```

这些检查分别覆盖：

- 脚手架继承约束是否被破坏
- API 与控制台引用是否一致
- Go 后端单元测试
- React 控制台生产构建

## 常见问题

### Q1：数据库启动失败

先确认 Docker 或本地 PostgreSQL 是否可用。如果只是演示核心链路，可以不配置 `ANJING_DATABASE_URL`，后端会使用内存存储。

### Q2：前端请求失败

确认后端运行在 `:19002`，并检查 Vite 代理配置是否指向同一个地址。

### Q3：为什么不需要单独启动多个后端服务？

这是脚手架习惯：同一仓库、同一套平台包、多个 Go 命令入口。课堂优先使用 `cmd/platform-all`，它会同时挂载客服、知识、运营相关 API。
